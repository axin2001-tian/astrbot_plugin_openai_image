# OpenAI 图片生成插件（astrbot_plugin_openai_image）

对接 OpenAI 图片生成/编辑 API（`gpt-image-1`、`dall-e-3`、`dall-e-2` 及各类 OpenAI 兼容中继）的 AstrBot 插件。

## 功能

- **供应商选择**：内置 OpenAI 官方、硅基流动 SiliconFlow 预设，也支持任意 OpenAI 兼容中转站。
- **/v1 自动隐藏与补全**：配置面板中的 API 地址只显示纯净根地址（如 `https://api.openai.com`），
  无论你填不填 `/v1`、甚至粘贴了完整的 `/v1/images/generations` 端点，插件都会自动识别、剥离并补全 `/v1`。
- **获取模型（与供应商配置相互独立）**：使用指令 `/模型` 即可获取当前供应商支持的图像模型列表，
  自动保存并提示你切换；不需要在供应商配置里捆绑任何模型逻辑。
- **模型按供应商自动获取（不依赖默认模型）**：`/draw` 时会自动拉取**当前供应商**的模型列表
  （带缓存、按供应商隔离），模型配置留空或所填模型不在列表中时自动选择可用图像模型并保存，
  不再依赖任何写死的默认模型；`/模型` 指令可强制刷新列表。
- **生成指令可自定义 + 收集模式工作流**：生成指令名可在配置面板自定义（配置项「生成指令名」）。
  发送生成指令（默认 `/draw`）后进入**收集模式**，之后发送的图片与文字都会自动收集；
  发送「开始」开始生成，「继续」继续收集，「取消」退出。
- **文字和图片收集**：进入收集模式时，指令参数、消息中直接附带的图片、引用消息中的图片与文字
  会作为**初始素材**；之后发送的素材持续追加。有图片时走图片编辑（`/v1/images/edits`），
  无图片时走文生图（`/v1/images/generations`）。
- **自动撤回状态消息**：收集模式的「已进入收集模式 / 已收集 / 继续收集中」等状态消息在发送
  「开始」或「取消」后自动撤回；「正在生成/编辑」进度消息在生成完成、结果即将发出前自动撤回，
  保持聊天整洁。仅在支持撤回的平台（QQ/OneBot）生效，其它平台自动忽略；可在配置面板「自动撤回状态消息」关闭。
- **指令**：`/draw`、`/模型`、`/设置模型`。

## 安装

1. 将整个 `astrbot_plugin_openai_image` 文件夹复制到 AstrBot 的 `data/plugins/` 目录下。
2. 在 AstrBot WebUI 的「插件管理」中启用该插件（必要时点击「重载插件」）。
3. 插件会自动安装依赖（`httpx`、`pillow`，均为 AstrBot 自带依赖，一般无需额外安装）。

## 配置

在 AstrBot WebUI 的插件配置面板中：

| 配置项 | 说明 |
| --- | --- |
| 中转站/站点列表 | **可添加多个中转站/站点**，每项包含：站点名称、API 地址（不含 `/v1`，自动补全）、API Key。参考地址：OpenAI `api.openai.com`、硅基流动 `api.siliconflow.cn`、阿里云百炼 `dashscope.aliyuncs.com/compatible-mode`、腾讯混元 `api.hunyuan.cloud.tencent.com`、302.AI `api.302.ai` |
| 当前站点 | 使用哪个站点（填站点名称；留空用第一个）。也可用 `/供应商 <站点名称>` 切换 |
| 主人用户 ID | 插件主人（全部权限，不受黑名单限制）。**设置后默认仅主人可用**，其他人需加入白名单 |
| 白名单用户 ID | 额外允许使用的用户；主人与白名单都未设置时，除黑名单外所有人可用 |
| 黑名单用户 ID | 禁止使用的用户（优先级最高，主人除外） |
| 生成指令名 | 自定义生成指令，如 `绘图`、`画图`。发送 `/<指令名>` 进入收集模式（默认 `/绘图`、`/画画`、`/生成图片` 可用，`/draw`、`/img` 仍兼容） |
| 图片模型 | **留空即可**：插件会自动根据当前供应商获取模型列表并选择可用的图像模型；也可用 `/模型` 查看列表后用 `/设置模型` 指定 |
| 图片尺寸 / 画质 / 生成数量 | 见各配置项的提示，插件会按模型自动修正不支持的取值 |
| 生成任务限流 | 默认 60 秒内最多 3 个生成任务，超出自动排队等待（可改次数/窗口，次数 0 表示不限） |
| 自动撤回状态消息 | 默认开启。收集模式的状态消息在「开始/取消」后撤回、「正在生成/编辑」进度在结果发出前撤回（仅 QQ/OneBot 平台生效） |

| 🔍 `/模型` | 获取当前供应商支持的图像模型列表（别名：`/获取模型`、`/刷新模型`） |

### 收集模式示例

```
方式一（默认指令名 + 逐步收集）：
用户：/绘图 一只猫
机器人：📥 已进入收集模式 📝 初始文字：5 字 ...
用户：[图片]（发送一张参考图）
机器人：✅ 已收集：图片 1 张，文字 0 段 ...
用户：把背景换成星空
机器人：✅ 已收集：图片 1 张，文字 1 段（共 7 字）...
用户：继续（想再发素材）/ 取消（退出）
用户：开始
机器人：🎨 正在编辑图片... → ✨ 已生成
```

```
方式二（引用消息作为初始素材）：
用户A：  [图片] 这是我家的猫
用户A（引用该消息）： /绘图 把背景换成星空
机器人：📥 已进入收集模式 🖼️ 已收集图片：1 张 📝 初始文字：7 字 ...
用户：开始 → 编辑生成
```

> 说明：群聊与私聊**都无需 `/` 前缀或 @ 机器人**，直接发送指令/素材即可（插件会监听所有消息并自动识别）。
> 引用消息中的图片能否收集取决于平台适配器是否在引用段携带原图
> （OneBot 等平台支持；微信个人号等部分平台可能仅携带文字），建议优先使用「消息中直接附带图片」。
> 收集模式空闲 30 分钟自动退出。

## 常见问题

- **获取模型为空**：检查供应商、API 地址（确保能访问）、API Key 是否正确；部分中继的 `/v1/models`
  接口未实现或需要额外权限。插件在未匹配到图像模型关键词时会退化为列出全部模型。
- **报错 `No image generation quota`（429）**：这是 OpenAI 上游返回的额度错误，**账号余额 ≠ 图片生成额度**。
  OpenAI 官方账号需在 Billing 充值且项目开通图片功能；中转站通常需要单独开通「图片生成」模型权限/额度
  （NewAPI 等系统按令牌分组控制模型权限，余额充足也可能没有图片额度），请联系中转站客服确认，
  或用 `/模型` 查看该供应商实际开放的图像模型。
  插件遇到该错误时会**自动尝试供应商列表中的其他图像模型**（最多换 4 个），
  全部失败后会列出失败模型并提示联系供应商；也可用仓库根目录的 `test_openai_image_api.py`
  脚本绕过插件直接测试 API，把原始响应发给供应商排查。
- **生成失败 / 报错**：报错信息会原样返回 API 的错误内容，如模型名不存在、尺寸不支持、额度不足等。
  部分中继不支持 `response_format=b64_json`，插件会自动降级重试（此时结果以 URL 形式下载）。
- **dall-e-2 编辑图片失败**：dall-e-2 的编辑接口严格要求**方形 PNG**（≤4MB），插件会尝试自动转换格式，
  若仍失败请更换图片或改用 `gpt-image-1` / `dall-e-3`。
- **群聊聊天/他人发图时误触发收集**：v1.4.0 起：① 免前缀的纯文字绘图指令（如 `画画 xxx`）进入收集前
  需回复「确认」；② 收集模式**仅发起者（或主人）**能投递素材和控制（开始/继续/取消），
  **其他人的消息一律静默忽略**（不会收集、不会回复）。请先对残留的旧会话发送「取消」退出。
- **只要图片生成、不想让机器人聊天**：本插件只做图片生成，不涉及对话。若机器人收到未处理的消息会走
  AstrBot 默认对话（可能提示「未找到任何可用的对话模型」），请在 WebUI 配置中**关闭「启用 AI 能力」**
  （对应 `cmd_config.json` 的 `provider_settings.enable = false`）。另外，收集模式激活时，
  无图无文字的杂消息（表情/语音/卡片等）会被插件静默吞掉，不会触发对话。
- **生成了图片但没有发出**：检查 AstrBot 全局配置 `platform_settings.only_llm_result` 是否为 `true`，
  该选项会屏蔽非 LLM 的插件消息，请关闭。
- **日志出现 `upload media to cdn failed: 500`（微信个人号 weixin_oc）**：这是**微信个人号网关的 CDN 上传服务端故障**，
  多为临时性问题。插件已自动重试发送（最多 3 次）；若持续失败，请重启网关/重新扫码登录，
  或联系网关服务商；也可在配置中把「图片尺寸」调小（如 1024x1024、画质 standard）降低上传体积。
- **收集的图片数量显示多于实际张数**：同一张图片可能以不同引用形式被收集（本地路径/URL/文件名，
  或引用消息与直接附图是同一张图）。插件 v1.2.4 起，**共享任意引用的图片会自动合并为一张**
  （引用形式不同的候选会合并保留，解析时逐个尝试）。若仍异常，请把日志中「收集模式：已收集素材」一行的
  `新增图片候选` 内容发来排查。
- **「开始」时提示未能获取已收集的图片（概率性）**：QQ 等平台的图片 URL 会过期、临时文件会被清理，
  收集到「开始」之间隔得越久越容易失效。插件 v1.4.5 起会在**收集图片的瞬间立即下载/复制到插件持久目录**
  （`data/plugin_data/astrbot_plugin_openai_image/images/`），「开始」时直接使用本地文件，不再依赖会过期的引用。
  若仍失败，请查看日志中「收集模式：图片候选均无法解析」一行，把候选引用发来排查。
- **QQ/OneBot 群聊收集图片后提示「未能获取已收集的图片」**：QQ 图片段的 `url` 可能为空/失效、
  `file` 只是协议端缓存名。插件会：优先使用适配器已下载的本地路径、依次尝试
  path/url/file 多候选引用、带浏览器 UA/Referer 重试下载、并调用 OneBot `get_image` API
  从协议端获取缓存文件，收集时即落盘。仍失败时请重新发送图片，或确认协议端
  （NapCat/LLOneBot 等）已开启图片下载功能。
- **收集了图片但生成的图没用上（或编辑报错）**：这是**供应商的图片编辑接口（/images/edits）不支持/形同虚设**——
  很多中转站只实现了文生图（/images/generations），编辑接口要么报错，要么返回 200 但实际没用上传的图。
  插件已支持：检测到编辑接口不支持时自动回退为仅文字生成并提示。
  可用 `test_openai_image_api.py` 脚本单独验证编辑接口（会提示查看生成结果里是否有测试标记）。
  如需真正"用你的图改图"，请确认供应商支持图片编辑（如 OpenAI 官方 gpt-image-1/dall-e-2），
  或换一家明确支持编辑接口的中转站。
- **报错 `failed to send message segment(s)`（如微信个人号 weixin_oc）**：这是**消息平台适配器发送失败**，
  不是图片生成失败。常见原因：① 图片过大/格式不支持（插件已自动把超大图压缩、WebP 等特殊格式转 PNG 后再发送）；
  ② 平台网关登录态/会话上下文失效；③ 网关上传接口异常。
  请查看 AstrBot 日志中对应适配器的详细报错（如 `prepare media failed`、`sendmessage failed`、`context token missing`），
  对应处理：重新扫码登录/重启网关、或缩小图片尺寸。
- **生成图片的存放位置**：`data/plugin_data/astrbot_plugin_openai_image/images/`，
  插件会自动清理（最多保留 200 张，超过 7 天删除）。

## 兼容性

- 面向 AstrBot v4（`_conf_schema.json` 配置体系）开发；在旧版本中可能退化为无配置运行，
  建议使用 AstrBot v4 及以上版本。
- 依赖 `httpx`、`pillow`（均为 AstrBot 核心依赖）。
